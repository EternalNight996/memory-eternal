# 设计规范与体验基线（DESIGN）

这份文档解决的不是「好不好看」，而是「为什么同一个东西在不同页面长得不一样、按钮等级分不清、
状态显示互相矛盾、空态只有一句『暂无数据』」。它给出**唯一口径**，新增/改动的界面按它来。

## 1. 现状审计（2026-11-13，`src/client/index.tsx` 单文件 11,150 行）

| 指标 | 数量 | 说明 |
|---|---|---|
| inline style 对象 | **527** | 同一件事各写一遍：间距、颜色、圆角 |
| 硬编码十六进制色 | **1,467** | 换皮肤靠 `[data-skin]` 覆盖选择器，覆盖不全就漏 |
| 硬编码 rgba | 517 | 同上（半透明层最容易被漏掉） |
| 硬编码 padding | 377 | 7px / 9px / 11px 这类随意值到处都是 |
| 硬编码字号 | 220 | 8.5 / 9 / 10.5 / 11.5 / 12.5 共七八档 |
| `mc-btn` 使用 | 160 | 只有「普通按钮」一种语义 |
| `me-on`（伪主按钮） | **50** | 一屏出现 3–5 个「主按钮」是常态 |
| toast / `setNote` | **159 / 30** | **两套提示机制并存**，同一次操作两种提示 |
| 空态文案 | 87 | 半数只有「暂无数据」，没有下一步 |
| loading 文案 | 111 | 全是「加载中…」，没有骨架屏 |

## 2. 五类系统性问题

1. **按钮等级失效**：`me-on` 被当作"高亮"到处用，导致「启动服务」和「关闭语义召回」并排都是红的，
   用户不知道先点谁。→ 规定**一屏最多一个 primary**。
2. **状态显示互相矛盾**：服务状态、向量覆盖、任务进度来自三个接口、三种文案，出现过
   「覆盖 7293/7293 + 任务 done」和「服务不可达」同屏（根因是探测参数没带，已在后端修成默认探测）。
   → 规定**状态一律用 `Status` 组件 + 单一数据来源**。
3. **两套提示**：`notify`（toast）与 `setNote`（行内小字）混用，同一操作有时 toast 有时小字。
   → 规定：**操作结果用 toast（一次性），字段级/持续状态用 `Hint`/`ErrorBar`（就地显示）**。
4. **空态与错误态太弱**：空态没有下一步、错误没有重试，用户只能刷新。
   → 规定：**空态必带 hint（+可选主操作）、错误必带重试或下一步**。
5. **多步任务没有步骤感**：语义召回、首次引导、备份恢复都是"点一下然后希望它自己好"。
   → 规定：**凡是超过一步的任务，用 `StepFlow` 显示①→②→③，并锁住未就绪的下一步**。

## 3. 设计令牌（`src/client/ui/design-tokens.js`）

| 维度 | 允许值 | 备注 |
|---|---|---|
| 间距 `space(n)` | 0 / 2 / 4 / 6 / 8 / 12 / 16 / 24 / 32 | 4px 基准，**不许 7/9/11** |
| 字号 `FONT` | 10 / 11 / 12 / 13 / 14 / 16 / 20 | 6 档，不许 10.5/11.5 |
| 行高 `LINE` | 1.35 / 1.55 / 1.7 | 正文默认 1.55 |
| 圆角 `RADIUS` | 6 / 10 / 14 / 999 | 卡片 10、按钮 10、chip 999 |
| 颜色 `COLOR` | 语义名（text/textDim/textMuted/panel/border/accent/success/warn/danger/info/mark） | **组件里不写色值** |
| 动效 `MOTION` | 120 / 180 / 260ms | 只做位移与透明度，不做花哨过渡 |

令牌同时铺成 CSS 变量（`--me-sp-*` / `--me-fs-*` / `--me-c-*`），**皮肤换色只覆盖变量**，不改组件。

## 4. 组件契约（`src/client/ui/components.jsx`）

| 组件 | 用法要点 |
|---|---|
| `<Btn variant size loading icon>` | `primary` 一屏最多一个；`secondary` 常规；`ghost` 弱化（行内文字按钮）；`danger` 破坏性操作；`size="sm"` 用于工具栏 |
| `<Status tone text sub>` | `tone = ok/warn/bad/idle`；状态全靠它，不许再手写圆点+文案 |
| `<EmptyState icon title hint action>` | `hint` 写"下一步做什么"，能给按钮就给 |
| `<ErrorBar error onRetry extra>` | 错误一律可就地重试或给下一步 |
| `<StepFlow steps current done>` | 多步任务；`current` 从 0 起，完成项打勾 |
| `<Skeleton h w>` | 加载态用它，替代「加载中…」 |
| `<Section title desc actions>` | 区块标题/说明/右侧操作的统一排版 |
| `<Hint tone>` | 行内持续提示（配置已保存、需要先启动服务…） |

四条硬规则：

1. **一屏最多一个 primary 按钮**（当前步骤的主操作），其余 `secondary` / `ghost`。
2. **状态只有一个来源**：服务状态来自 `/embedding/service`，覆盖率来自 `/embedding/status`，不各自拼。
3. **同一次操作只提示一次**：动作结果 → toast；持续状态 → `Hint` / `ErrorBar`。
4. **不能说"暂无数据"就完事**：空态必须告诉用户下一步。

## 5. 落地顺序（低风险推进）

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 建令牌与组件层（**不改主文件**，先让契约存在） | ✅ 已完成（`src/client/ui/`） |
| 2 | 语义召回：下拉挪到标题右侧、启停与启用合并成一颗主按钮、只有本地模式出现服务、步骤锁 → 用 `StepFlow`/`Btn`/`Status` 重写 | 进行中 |
| 3 | 关键页接入：知识卡片列表（空态/加载骨架/错误重试）、统计健康页（状态来源统一）、审核与回收（批量操作按钮等级） | 待排 |
| 4 | 防回归：令牌值域与组件渲染的单测（`tests/ui-tokens.test.mjs`）、每屏 primary 数量与空态 hint 的源码守卫 | 待排 |

旧代码不动大手术：**改到哪块就把哪块换成组件**，避免一次性重排 11k 行带来的回归风险。

## 6. 防回归清单（测试守什么）

- 令牌值域固定（间距/字号/圆角只允许上表的值），`space()` 越界要夹取而不是返回 NaN；
- `Btn` 的 class 组合正确（`me-btn--primary|secondary|ghost|danger`、`--sm`），`loading` 时禁用；
- `StepFlow` 正确标记 `done` 打勾、`current` 高亮；
- `EmptyState` 渲染 `hint`；`ErrorBar` 在 `onRetry` 存在时渲染重试按钮；
- `TOKENS_CSS` / `COMPONENTS_CSS` 覆盖全部变量与变体（防止改令牌忘了同步 CSS）。

## 7. 浮层与遮挡（「下拉看不全」是一类可复现的结构缺陷）

典型症状：配置卡片里的多选下拉一展开，底部几行被 sticky 底栏（`重置 / 保存配置`）盖住。
根因不是"样式不好看"，而是两条硬约束没被遵守：

| 约束 | 要求 | 现状 |
|---|---|---|
| 层级 | 面板内浮层 `z-index ≥ 1200`；sticky 栏是 20–24，导航栏是 23 | 已修（`MultiDD` 原来只有 20，正好卡在底栏下面） |
| 方向 | 展开前**测量视口**：下方空间 < 200px 就向上弹（`bottom:100%`） | 已修（`measure()` 监听 resize / scroll 重算） |
| 高度 | `maxHeight = min(320, 视口剩余)`，浮层内滚动但不出屏 | 已修（原来写死 180） |
| 祖先裁切 | 浮层所在容器的祖先链不得有 `overflow: hidden` | 已核（`.mc-card / .mc-cfg-sec / .mc-field` 均无裁切） |

新增浮层（下拉、菜单、气泡、图例）时按这四条做，别只调颜色。已知同类元素：`me-graph-legend-pop`、
`me-graph-ctxmenu`（z=31，在画布层内可接受）、`me-graph-sidebar`——后两个在固定画布容器里，层级另算。
