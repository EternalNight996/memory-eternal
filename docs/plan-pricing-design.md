# memory-eternal 云端套餐设计方案（待 YG 拍板）

> 起因：用户原话「订阅套餐去掉无关的 单独 memory-eternal 云端套餐 重新设计与定价」。
> 这份文档只做**决策依据 + 建议方案**，价格最终由 YG 定。

## 一、为什么现在的套餐不对

生产 `GET /cloud/billing/plan` 返回：

```json
{ "plan": "free", "plans": ["personal", "pro", "max"], "canCheckout": true }
```

MengBot 订阅页（`pay.mengbot.com.cn/subscribe`）的实际档位：

| SKU | 价格 | 权益 |
|---|---|---|
| `sub-personal` | ¥39/月（原价 ¥59） | 云端桌面（按需加购）、最多同时 5 个任务、共享云加购 ¥119/月 4C4G、每日备份保留 14 天 |
| `sub-pro` | ¥79/月（原价 ¥99） | 每月 ¥30 额度直送（官方价 +20%）、云端桌面… |
| `sub-max` | （未抓全，页面更长） | … |
| `sub-merchant` | ¥199/月 | 商户接入（50,000 卡 / 600 rpm / 10 库） |
| `sub-merchant-pro` | ¥999/月 | 商户旗舰（500,000 / 2,000 / 50） |

**问题**：`personal/pro/max` 是「把**机器人**放云端跑」的套餐 ——
云端桌面、并发任务数、共享云加购这些权益，**memory-eternal 用户一个都用不上**。
他真正需要的是：**存我的知识卡 + 让我随时随地搜得到**。

## 二、真实成本（用真实数据算）

本机库实测：

```
7,583 张卡 + 47 张隔离卡 = 115.5 MB
正文平均 2,584 字（≈8 KB UTF-8）
单卡 ≈ 8 KB，加 FTS 索引约 ×1.4 ≈ 11 KB
```

| 规模 | 存储 | 月存储成本（按对象存储 ¥0.12/GB） |
|---|---|---|
| 5,000 卡 | ≈ 55 MB | ¥0.007 |
| 50,000 卡 | ≈ 550 MB | ¥0.07 |
| 200,000 卡 | ≈ 2.2 GB | ¥0.26 |

**结论：存储几乎不花钱**。真正的成本在：

1. **API 调用**（`/lookup` 批量查询、`/write`、`/import`）—— 按 rpm 限速即可控；
2. **带宽**：一次全量导入 115 MB；按云厂商 ¥0.5/GB 出流量算，**一次导入 ≈ ¥0.06**；
3. 如果云端要跑**蒸馏**（现在是本地做），才会产生 LLM 成本 —— 当前云端不蒸馏。

按 200 rpm × 30 天满打满算 ≈ 860 万次/月，单次 5 ms + 200 字节响应 ≈ 1.7 GB 出流量 ≈ ¥0.85。
**一个用户跑满一个月，成本也在 ¥1 量级。**

## 三、建议方案（三档，只保留 memory-eternal 需要的维度）

| 档位 | 建议价 | 卡片上限 | 请求速率 | 库数 | 带宽/月 | 适用 |
|---|---|---|---|---|---|---|
| **基础版** | ¥9/月（年付 ¥90） | 5,000 | 60 rpm | 1 | 2 GB | 个人轻度：一两个项目 |
| **标准版** | ¥29/月（年付 ¥290） | 50,000 | 300 rpm | 3 | 10 GB | 个人重度：多年知识库 |
| **团队版** | ¥99/月（年付 ¥990） | 200,000 | 1,000 rpm | 10 | 50 GB | 小团队共用 |

**对比 MengBot 个人版 ¥39**：memory-eternal 基础版 ¥9 更便宜，
因为**不提供云端桌面、不跑机器人**，只有存储 + 检索 API。

**商户档不变**（已有 `sub-merchant` ¥199 / `sub-merchant-pro` ¥999），
因为那是「把 memory-eternal 接进自己的产品」的 B 端场景，与个人档不冲突。

## 四、需要 MengBot 做的

1. **开三个新 SKU**：`sub-me-basic` / `sub-me-std` / `sub-me-team`
   （或复用 `sub-personal` 但把权益文案改成 memory-eternal 相关 —— 不建议，会与机器人套餐混淆）
2. **webhook `entitlement.updated` 里带上 caps**：`{ cards, rpm, vaults, bandwidthGB }`
   —— 现在 `caps: null`，我们的 UI 只能显示"当前套餐"四个字，没法告诉用户"你还能存多少张"
3. **订阅页 `?source=memory-eternal` 时只显示 memory-eternal 的档位**
   （现在是通用页，混着机器人套餐）

## 五、我们这边会同步做的

- `planLabelOf()` 补齐中文名与权益（现在只认 `sub-merchant*`，
  遇到 `personal/pro/max` 会显示英文原始值）
- 套餐卡显示：名称 / 价格 / 到期 / 卡片用量（x / 上限）/ 速率 / 升级续费深链
- 去掉与 memory-eternal 无关的权益描述（云端桌面、并发任务、共享云加购）

## 六、待 YG 决策的点

1. **三档价格**（¥9 / ¥29 / ¥99 是建议值，可以改）
2. **卡片上限**（5k / 50k / 200k 是我按"单卡 11 KB"推的，若你打算限制得更紧可以往下调）
3. **要不要送免费额度**（比如注册送 1,000 卡永久免费 —— 现在 `plan: free` 就是这个意思，
   但 `caps: null` 说明还没有具体限制）
4. **年付折扣**（建议 年付 = 10 个月价，即省 2 个月）

定了之后我改 `planLabelOf` + 套餐卡 UI，并把 SKU 请求发给 MengBot。
