Why another memory

不是又一个向量库。
是你能打开、能审、能回滚的记忆。

相似度解决“像不像”，不解决“对不对”。memory-eternal 把记忆做成可检查的 Markdown 卡，再决定它是否进入主库。

Embedding 给你相似，Markdown 给你可读。审核给你可控。 不是否定向量检索，而是换一种取舍：本地、可解释、可审计。先让记忆能被信任，再让它变聪明。

The loop

一次对话，四步变成记忆。

没有额外操作。会话结束自动发生，你只需要在审核中心做“保留还是丢掉”的决定。

01 / CAPTURE

捕获

监听会话事件，过滤掉寒暄和噪音，留下有信息量的片段。

02 / DISTILL

蒸馏

模型把片段压成一张卡：结论、依据、边界，写进本地 Markdown。

03 / REVIEW

审核

新卡先进入隔离区。批准才进主库，驳回进回收站，全部可撤回。

04 / RECALL

召回

Agent 需要历史时只取相关小块，不把整段对话塞回 prompt。

Install

两条命令，开始积累。

DSH 用户走插件市场；其它 Agent 装 CLI 后 `connect` 一次，MCP 与 hooks 自动接线。

DeepSeek Harness推荐
# 桌面版：设置 → 插件 → 搜 memory-eternal
dsh plugin --profile desktop add memory-eternal

# 浏览器版
dsh plugin --profile web add memory-eternal

# 验证后重启宿主
node -e "console.log(require('memory-eternal/package.json').version)"
Claude Code / Codex / CursorMCP + hooks
npm i -g memory-eternal

dsh-memory connect claude   # Claude Code
dsh-memory connect codex    # Codex / Codex Desktop
dsh-memory connect cursor   # Cursor

# 不装 Agent，也能单独打开 Web UI
dsh-memory open
全部写入 ~/.dsh/memory-vault。不需要 GPU，不需要云 API key，不把记忆发到第三方。
FAQ

你大概会问的几件事。

记忆会上传到云端吗？

不会。默认全部在本机：Markdown 存在本地 vault，索引在 SQLite，插件不依赖外部网络。只有配置了蒸馏用的模型接口时，才会把“待蒸馏的会话片段”发给你指定的模型服务。

和 Claude Code 自带的记忆冲突吗？

不冲突。它只写自己的 MCP 键和 hooks，不读也不改其它记忆插件的数据。四个 Agent 共用同一个 vault，但每张卡记录作者，审核中心统一管理。

为什么不用向量数据库？

不是不用，是先不把它作为唯一入口。标签、中文片段、结构化字段已经能覆盖大量“找回上次结论”的场景，而且结果可解释。需要语义检索时再加，不是一开始就把记忆变成黑盒。

会一直烧 token 吗？

沉淀只在会话结束触发，召回只取相关小块，并有上限。还有“省钱包”配置：冷却时间、候选数量、模型轮换。具体消耗取决于你的对话量和模型。

能导出、能备份、能删吗？

能。知识库是 Markdown + SQLite，可以 git 管理、导出 MD/JSON；删除先进回收站，30 天后清理；每天自动备份，保留 7 天，支持一键恢复。
